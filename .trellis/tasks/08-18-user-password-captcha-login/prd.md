# 完善用户密码与图形验证码登录

## Goal

在现有手机号用户身份和 HttpOnly Cookie 会话基础上，增加真实的“手机号/账号 + 密码 + 图形验证码”登录链路，使用户端不依赖未配置的短信供应商也能使用密码登录。

## Requirements

- 用户账号沿用现有 `User.phone` 字段，前端登录字段命名为手机号/账号；本任务不引入第二套 username 身份体系。
- 新增密码哈希存储，禁止保存明文密码、在日志中记录密码或在 API 响应中返回密码信息。
- 新增服务端生成的 SVG 图形验证码，验证码答案只保存哈希，具备过期、失败次数上限、一次性消费和按客户端限流。
- 新增密码登录 API 和用户端登录页面，登录成功后继续使用现有用户 Cookie session 和回跳逻辑。
- 保留现有短信验证码接口和协议登录接口；短信供应商未配置时仍明确返回服务未配置，不用 mock 替代真实短信服务。
- 错误响应统一使用现有 `ApiException`/`ApiError` 契约，不暴露账号是否存在、密码是否正确或验证码内部状态。
- 不修改 `bak/`，不使用 MockMvc、WireMock 或外部供应商 mock。

## Acceptance Criteria

- [ ] 数据库新增可空密码哈希字段和图形验证码挑战表，版本化迁移可重复执行且不影响已有用户和会话。
- [ ] `GET /dream_web/auth/captcha` 返回挑战 ID、过期时间和仅通过图片呈现答案的 SVG 数据，不额外返回明文答案。
- [ ] `POST /dream_web/auth/password-login` 校验协议、验证码、手机号和密码，并成功写入现有 `dreamspace_session` Cookie。
- [ ] 验证码过期、错误达到上限、重复消费和客户端发放超限均被拒绝。
- [ ] 未设置密码的旧用户和不存在的用户返回相同的通用认证错误，避免账号枚举。
- [ ] `dream_web` 登录页面完成账号、密码、图形验证码刷新、错误、加载和登录意图回跳状态。
- [ ] API 服务测试、验证码测试、前端类型检查/构建通过；不新增 MockMvc 测试。
