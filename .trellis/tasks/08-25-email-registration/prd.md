# 邮箱验证用户注册

## Goal

为普通用户增加邮箱注册流程。邮箱必须经过验证码验证后才能创建账号并建立现有的 HttpOnly Cookie 会话；邮箱域名仅允许 `qq.com`、`163.com` 和 `foxmail.com`。

## Requirements

- 注册账号使用邮箱作为唯一身份；现有手机号账号、短信登录和密码登录接口继续可用。
- 邮箱地址去除首尾空白并按小写比较；格式必须包含非空本地部分和允许的域名，其他域名拒绝。
- 新增发送邮箱验证码接口。验证码只保存哈希，具备有效期、失败次数上限、一次性消费、按邮箱/IP 限流；响应不得包含验证码明文。
- 新增注册接口，校验邮箱验证码、密码长度（8-72 个字符）和三类协议；成功后写入用户、协议接受记录和现有 `dreamspace_session` Cookie。
- 邮件发送使用可配置 SMTP；未配置或发送失败时返回统一的服务不可用错误，不返回验证码或在日志中记录验证码、密码和完整邮箱。
- 不通过注册接口泄露邮箱是否已注册；发送验证码对已注册邮箱使用统一响应，最终注册失败使用通用错误。
- 现有用户数据与手机号登录行为不变；手机号字段改为可空以支持邮箱-only 账号，手机号登录仍要求手机号格式。
- 前端支持邮箱、密码、验证码、协议勾选、发送倒计时、加载/错误状态、登录与注册切换及 `returnTo` 回跳；中英文文案与现有认证页一致。

## Acceptance Criteria

- [ ] 版本化迁移为 `User.email` 建立唯一索引并允许 `phone` 为空，新增注册验证码表及索引。
- [ ] `POST /dream_web/auth/register/codes` 只接受三个邮箱域名，成功发送时返回挑战 ID、过期时间和重试等待秒数，不返回验证码明文。
- [ ] `POST /dream_web/auth/register` 验证验证码、密码和协议，创建用户、保存密码哈希、记录协议并设置现有会话 Cookie。
- [ ] 验证码过期、错误达到上限、重复消费、邮箱/IP 发放超限和 SMTP 未配置均得到稳定的统一错误码。
- [ ] 重复邮箱、非法域名、非法格式不会创建第二个用户，且不会暴露已注册状态。
- [ ] API 单元/契约测试覆盖域名策略、验证码生命周期、密码哈希、注册事务和 SMTP 不可用；迁移资源测试通过。
- [ ] `dream_web` 类型检查、构建和认证页交互验证通过；不新增 MockMvc、WireMock 或外部供应商 mock。
