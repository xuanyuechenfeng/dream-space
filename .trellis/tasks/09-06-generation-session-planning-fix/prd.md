# 修复生成会话时序与图片数量确认卡住

## Goal

保证每次生成任务都归属于一个已正式持久化的会话，并保证预规划阶段的状态只出现在所属会话中；同时让图片数量确认阶段具备可观测、可恢复的终态，避免模型调用完成后页面仍显示无期限的“确认图片数量”。

## Requirements

1. 新会话提交必须先调用正式会话创建接口，拿到 `sessionId` 后才能创建预规划或生成任务。
2. 预规划、正式任务创建、重试、继续生成和全部重新生成都必须携带并校验所属会话；服务端不得为新的 v2 请求隐式创建无归属会话。
3. 提交中的本地状态必须按会话归属保存和恢复。打开历史会话时，只展示该会话的 pending/preflight 状态；不能把新会话任务展示到所有历史会话。
4. 会话切换、刷新、路由恢复、网络重试和正式任务响应丢失时，必须保持幂等键与会话绑定，不得重复创建任务或把任务迁移到其他会话。
5. 预规划状态必须可观察：至少记录 preflight ID、session ID、任务/预规划阶段、模型调用耗时、响应长度/形状、最终状态和错误码；不得记录密钥、完整图片或完整 provider payload。
6. Worker 完成或失败后必须写入可检索的终态事件；API SSE 断开时前端继续以状态轮询为准，不能因 SSE 结束而永久停留在准备中。
7. 超过配置阈值仍未完成的预规划必须进入明确失败终态并允许重试；恢复过程不能扣费、创建半成品任务或遗留不可删除的活动状态。

## Constraints

- 保留现有 v1 单图任务的历史数据可读性和幂等重试语义。
- 预规划本身不计费；额度只在正式任务/执行创建事务中预留。
- 会话删除仍由服务端活动任务/预规划保护规则决定，前端不能用 pending 状态伪造服务端任务。
- 不修改现有已应用迁移；需要数据库字段或索引时新增迁移。

## Acceptance Criteria

- [ ] 新会话发送时，网络时序为 `POST /sessions` 成功后才发送 `/preflights`，随后才创建正式任务；会话列表立即出现该会话。
- [ ] 服务端收到缺少 `sessionId` 或会话不属于当前用户的 v2 预规划/任务创建请求时返回明确 4xx 错误，不创建任务、不扣额度。
- [ ] 在会话 A 生成尚未完成时打开会话 B，B 不显示 A 的 pending 卡片；返回 A 后可恢复显示 A 的真实预规划状态或正式任务。
- [ ] 刷新页面、SSE 断线、正式创建响应丢失后，使用同一会话和幂等键恢复；最多产生一个正式任务。
- [ ] 日志能关联一次请求的 `preflightId/sessionId`，并能区分“模型调用耗时”“已 READY”“终态失败”“超时恢复”。
- [ ] 日志所示模型已返回并解析后，前端通过轮询或 SSE 在一个轮询周期内显示正式任务或明确失败，不会无限显示“确认图片数量”。
- [ ] 预规划超时被标记为终态、可重试且不产生额度账务残留；相关 API、Worker、前端单元测试及端到端关键流程通过。

## Out of Scope

- 不改变图片模型本身的生成质量、提示词策略或计费规则。
- 不把预规划过程转换为可计费的正式任务。
