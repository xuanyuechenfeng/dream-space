# 管理端运营能力详细设计

## Goal

基于当前仓库真实实现，识别管理端十一项运营能力的完成状态，并形成可直接拆分开发任务的详细设计，覆盖权限、数据、接口、页面、流程、审计、监控、迁移和验收。

## Requirements

- 分析用户管理、管理员与角色、权限配置、模型与供应商、模型路由与降级、计费规则、额度赠送与扣减、账单与收入报表、系统配置、审计查询、运营看板。
- 每项能力必须标注 `已实现`、`部分实现` 或 `未实现`，并引用当前代码或数据结构作为判断依据。
- 设计必须延续现有用户、额度、订单、生成任务和管理认证模型，不重复建设已交付能力。
- 权限由数据库 RBAC 管理，服务端以权限码鉴权；前端权限仅用于隐藏或禁用入口。
- 供应商凭据只保存外部密钥引用；项目 YAML 中现有测试配置保持不变。
- 额度变更必须写不可变流水，扣减不得导致可用额度为负，高风险操作需要复核。
- 计费规则、模型路由和系统配置均采用版本化发布、可预览、可回滚的治理方式。
- 财务报表、运营指标和运行时监控必须明确分层，不混用统计口径。
- 输出开发阶段、依赖关系、验收标准和回滚方案。

## Acceptance Criteria

- [x] 十一项能力均有现状结论和缺口说明。
- [x] 提供领域边界、核心状态机、数据表字段及约束。
- [x] 提供管理端 API、权限码和默认角色矩阵。
- [x] 提供管理端页面、交互和高风险操作流程。
- [x] 提供一致性、缓存、安全、审计和可观测性设计。
- [x] 提供分阶段实施顺序、迁移/回滚和可执行验收清单。
- [x] 正式文档落入 `docs/design/` 并加入目录索引。

## Constraints

- 本任务只交付设计文档，不修改业务实现或数据库迁移。
- 保留工作区中其他任务的未提交变更。
- `trellis-brainstorm` 技能在当前工作区不可用，本任务通过读取工作流、代码、迁移和现有设计完成等价需求核验。
