# 图片生成参数与图片角色自动识别

## Goal

优化用户端图片生成工作台，使用户可明确选择输出比例、分辨率和像素尺寸，同时取消前台对图片 A/B 的人工指定，由真实多模态规划模型结合提示词和上传图片内容自动识别生成意图及素材角色。

## Requirements

- 前台继续统一使用 `AUTO` 模式，不展示文生图、调整图片、图片重构选择。
- 支持 `smart`、`21:9`、`16:9`、`3:2`、`4:3`、`1:1`、`3:4`、`2:3`、`9:16` 和自定义尺寸。
- 支持服务端启用的 2K、4K 分辨率，宽高以 64 px 为步长并受最大边、最大像素约束。
- 本期每个任务固定只生成 1 张图片，不展示图片数量控件，创建请求不接受 `imageCount`。
- 前台最多上传两张无角色素材，只显示素材 1/2，不显示或提交图片 A/B。
- API 输入使用 `imageIds`，不接受 `targetImageId`、`referenceImageId`。
- Worker 使用真实多模态规划模型，根据用户提示词和图片内容识别 `TARGET_A`、`REFERENCE_B`、`UNUSED`。
- 上传顺序不得作为 A/B 判断依据；低置信度、角色缺失或冲突时任务明确失败并释放额度。
- 用户选择的比例、分辨率和尺寸是硬约束，贯穿规划、Prompt、图片模型调用和质量评估。
- 不增加 mock、WireMock 或外部供应商替身。
- 不修改 `bak/`。

## Acceptance Criteria

- [ ] 生成页提供比例、分辨率和宽高尺寸控件，桌面与移动布局无溢出或遮挡。
- [ ] 页面不存在图片数量选择，所有新任务固定 `imageCount=1`。
- [ ] 前端创建请求仅提交 `imageIds`，不存在旧角色字段和 `imageCount`。
- [ ] API 对比例、分辨率、宽高、图片归属和幂等参数执行完整服务端校验。
- [ ] 2K/4K 额度由服务端 options 返回并按单图预留。
- [ ] Worker 输出经过强类型和业务校验的图片角色分配。
- [ ] 调换上传顺序不会通过本地顺序规则改变图片角色。
- [ ] 角色歧义返回 `GENERATION_IMAGE_ROLE_AMBIGUOUS` 并释放额度。
- [ ] 图片模型请求包含最终比例、分辨率、宽高及经验证的目标/参考图片。
- [ ] 数据库迁移新增必要字段、约束且不修改已执行迁移。
- [ ] 前端类型检查、构建、单元测试与后端 Maven 测试通过。
- [ ] 真实供应商联调保留为人工验收，不以 mock 结果替代。
