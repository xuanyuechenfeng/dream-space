# 多图片生成与失败续生成

## Goal

让用户通过一次输入获得 1-4 张彼此有明确关系的图片。系统在每张图片成功时立即展示并独立扣费；部分失败或取消后保留成功结果，默认只继续生成缺失图片。

## Background

- 当前草稿和创建请求没有数量字段，前端将 `imageCount` 固定为字面量 `1`（`dream_web/src/api/client.ts:99-106`；`dream_service/api/src/main/java/com/dreamspace/api/service/GenerationService.java:81-105`）。
- 当前任务插入 SQL 固定写入 `imageCount=1`，数据库 CHECK 也强制单图（`dream_service/common/src/main/java/com/dreamspace/common/persistence/generation/GenerationMapper.java:36-41`；`dream_service/common/src/main/resources/db/migration/20260819100000_add_generation_dimensions_and_image_ids.sql:12-17`）。
- 当前 Worker 整批生成、审核、持久化后才一次性结算总额度，尚无逐张持久化、逐张结算和逐张事件（`dream_service/worker/src/main/java/com/dreamspace/worker/generation/GenerationProcessor.java:79-116`；`dream_service/worker/src/main/java/com/dreamspace/worker/generation/JdbcGenerationWorkerStore.java:99-118`）。
- 当前前端收到任务 SSE 事件后重新拉取完整任务，没有单张结果事件（`dream_web/src/stores/generation.ts:298-320`）。
- 当前重试会创建参数相同的新任务，无法在原任务上复用成功结果或只补齐缺失位置（`dream_service/api/src/main/java/com/dreamspace/api/service/GenerationService.java:213-220`）。
- 现有额度语义是任务受理时 `RESERVE`，成功后 `CONSUME`，失败或取消后 `RELEASE`；多图仍须保持这一账本不变量（`CONTEXT.md`）。

## Requirements

### R1. 数量解析与预规划

1. 单次任务目标图片数量为 1-4。
2. 数量参数提供“自动、1、2、3、4”，默认自动。自动模式采用提示词或集合结构中的明确数量，未声明时为 1；手动数量是最终数量。
3. 提示词只有数字数量且与手动参数冲突时，按参数执行并提示最终数量。提示词包含可枚举的不同槽位时，手动数量必须与槽位数一致，否则阻止创建并列出槽位，不得删除、合并或截断。
4. 自动识别到超过 4 个槽位、混合输出规格、事实不足、槽位划分歧义或低置信度时，要求用户修正；不创建任务、不预留额度。
5. 所有 1-4 张请求统一执行不计费的异步集合预规划。API 创建 preflight 后由 Worker 完成真实模型规划；一次用户点击在无冲突时自动等待预规划并完成正式创建，不增加第二次确认。
6. 预规划就绪后返回冻结计划摘要、目标数量、预计额度和绑定规范化输入的单次 `planToken`。Token 自预规划进入 READY 起有效 10 分钟；输入修改后失效，预规划与正式创建分别幂等。

### R2. 图片集合计划

1. 每个任务只有一份冻结的图片集合计划，类型为：同一意图的独立方案 `VARIATIONS`、沿明确维度变化的系列 `DIMENSIONAL`，或总结/流程/分镜等不同职责系列 `SEQUENCE`。
2. 集合计划包含共享事实、主体、受众、视觉规范和连续性约束，以及数量与目标数完全相同的有序结果槽位。
3. 每个槽位包含短标签、职责、内容范围、差异要求、独立 Prompt 和验收约束。集合规划不得编造业务事实、流程、顺序、数字、文案或职责；可以补全不改变意图的构图、镜头、光线、材质和装饰。
4. “春夏秋冬各一张”须形成四个季节槽位并保持核心场景一致；“总结图 + 流程 1/2/3”须形成一个概览槽位和三个步骤槽位，整组覆盖原描述且每张只展开自身范围。
5. 集合计划在预规划后冻结。自动恢复和继续缺失必须复用原槽位 Prompt；全部重新生成创建独立新任务，可以重新预规划。
6. 同一任务所有槽位共享比例、分辨率、宽高、模型、参考素材和单张定价。混合规格必须拆成多个任务。

### R3. 串行生成与增量返回

1. Worker 按槽位 1 到 N 严格串行，每次供应商调用只请求 1 张。当前槽位完成审核、持久化和扣费后才可启动下一槽位。
2. 每张成功图片立即产生可靠事件并在原槽位展示，不等待整组完成。
3. 可重试供应商错误和已有质量修复均属于当前槽位的受限自动恢复，不额外计费。只有不可重试错误或恢复次数耗尽后，槽位才最终失败并阻止后续槽位启动。
4. Worker 重投或重启后跳过成功槽位，从当前首个未成功槽位恢复；不得重新规划、覆盖成功结果或重复扣费。

### R4. 额度结算

1. 正式创建时按 `目标数量 × 冻结单张价格` 一次性预留全部预计额度。余额不足时原子拒绝任务创建，不产生部分预留。
2. 每个槽位成功后立即从该执行批次的预留额度中消费一张费用，且恰好消费一次。
3. 失败或取消时释放当前执行批次中所有未成功槽位的剩余预留；已经成功图片的消费不退款。
4. 继续缺失只预留缺失槽位费用，并继续使用原任务冻结的单张价格；全部重新生成的新任务预留完整目标数量费用。

### R5. 失败、取消与重新生成

1. 某槽位最终失败后，任务以成功数量区分 `FAILED` 或 `PARTIALLY_SUCCEEDED`，保留成功结果；当前失败槽位与后续尚未启动槽位必须可区分。
2. “继续生成缺失图片”在原任务上处理全部未成功槽位，复用冻结计划，不触碰成功槽位。
3. “全部重新生成”以原生成输入和完整目标数量创建新的独立任务，不保存来源任务关联；原任务和原图片继续可查看、下载。
4. 用户取消时保留已成功槽位和消费，停止当前槽位且不启动后续槽位，释放全部未成功预留。取消后迟到的供应商结果必须丢弃且不得扣费。
5. 已取消任务允许继续生成全部缺失槽位，也允许全部重新生成。

### R6. 前台展示

1. 正式任务创建后立即按计划顺序预展示全部带短标签的槽位，稳定呈现等待中、生成中、已完成、未完成、尚未生成和已取消状态。
2. 成功图片只替换对应占位，不改变槽位顺序或造成明显布局跳动。
3. 任务汇总实时展示完成数、目标数和实际消费额度；部分失败或取消后提供“继续生成缺失图片”和“全部重新生成”两个不同操作。
4. 单图仍按同一协议执行，但用户侧单图体验、比例、尺寸、素材、会话和下载能力不得回归。

### R7. 一致性与安全

1. 预规划、正式创建、执行批次、结果槽位、结果持久化、额度结算和事件均须有稳定幂等键。
2. 队列重复投递、并发继续、SSE 重连、网络响应丢失和取消/成功竞态不得造成重复任务、重复结果、重复预留或重复消费。
3. 事件和日志不得包含完整 Prompt、凭据、供应商响应或可访问的 `planToken`。

## Acceptance Criteria

- [x] AC1: 自动/手动数量覆盖 1-4；纯数字冲突按参数并提示，结构化槽位冲突、超过 4 个槽位和混合规格均在创建前阻止。
- [x] AC2: 单图与多图均经异步预规划；无冲突时一次点击自动等待并创建，预规划失败或澄清时不存在任务和额度流水。
- [x] AC3: `VARIATIONS`、`DIMENSIONAL`、`SEQUENCE` 分别通过“4 个方案”“春夏秋冬”“总结 + 流程 1/2/3”契约场景，槽位 Prompt 和标签与用户事实一致。
- [x] AC4: 多图严格串行；槽位 N 完成审核、持久化和消费前不启动 N+1，N 最终失败后不启动后续槽位。
- [x] AC5: 每张成功后通过 SSE 立即出现在固定槽位，任务和额度汇总同步更新。
- [x] AC6: 创建时一次预留完整预计成本；每个成功槽位恰好消费一次；失败/取消只释放未成功槽位额度。
- [x] AC7: 自动重投、Worker 重启和继续缺失均跳过成功槽位并复用冻结 Prompt；重复消息和请求不重复生成或计费。
- [x] AC8: 取消后无新结果和新消费，迟到结果被清理；成功图片保留，全部缺失槽位可继续。
- [x] AC9: 全部重新生成创建无来源关联的新独立任务并完整计费，原任务和结果保持不变。
- [ ] AC10: 桌面和移动端预展示全部槽位，无横向溢出、重叠或明显布局跳动；单图既有功能回归通过。单元测试和构建已通过，Playwright 多视口尚未执行。
- [x] AC11: 对账能够证明每个执行批次 `RESERVE = CONSUME + RELEASE`、每个成功槽位存在唯一消费、账户余额投影无漂移。

## Constraints And Out Of Scope

- 单任务上限不超过 4 张。
- 不支持同一任务内槽位级比例、尺寸、模型、素材或价格差异。
- 不把 Harness 对同一槽位的质量修复迭代视为新的计费图片。
- 不删除、替换或退还已经成功生成的图片。
- 不在本任务中扩展到用户手动编辑每个槽位 Prompt；用户通过修改原始输入重新预规划。
