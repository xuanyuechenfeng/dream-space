# 优化账单记录与生成页新会话体验

## Goal

让用户进入生成页时明确地开始一段新创作，避免被最近会话内容打断；让账单记录聚焦于对用户有意义的额度变化，同时保持后台审计所需的完整流水。

## Background

- 当前 `useGenerationStore.load()` 在没有 `sessionId` 时会自动打开排序后的第一条历史会话，因此 `/generate` 首屏展示最新历史内容。
- 当前生成提交接口支持省略 `sessionId`，由服务端在同一提交流程中创建会话并返回会话与任务；前端无需先创建空会话。
- 当前用户账单页面 `AccountView.vue` 直接展示 API 返回的所有额度流水，包含 `RESERVE`（生成预留）和 `RELEASE`（预留释放）。
- 生成页已有空态标题、说明、示例提示词和 composer，但部分样式来自未提交的现有工作；本任务必须保留这些改动并在其上完成行为修正。
- 管理员账单查询用于运营与审计，不应因用户展示优化而丢失预留/释放流水。

## Requirements

1. 用户账单记录隐藏 `RESERVE` 和 `RELEASE` 类型，列表总数、分页和空态均基于过滤后的结果；其余额度流水（当前为 `GRANT`、`CONSUME`）继续展示。管理员账单查询保持完整流水。
2. 访问 `/generate`（无 `sessionId`）时不自动打开任何历史会话，也不创建仅含草稿的会话。页面展示新会话空态：标题、说明、三个示例提示词，以及底部输入/生成控件。
3. 用户点击生成（或按 Enter 提交有效提示词）时，沿用现有提交 API 的无 `sessionId` 逻辑原子创建新会话并生成首个任务；成功后路由切换到新会话地址，历史列表更新。
4. 用户点击历史会话、带 `sessionId` 直接访问、或点击“新建会话”时，仍可进入/查看对应会话；“新建会话”应回到无活动会话空态，而不是制造空历史记录。
5. 按参考截图调整生成页空态的视觉层级：主要内容、示例提示词和 composer 在可用宽度内居中，桌面/平板/移动端均不产生横向溢出；既有生成对话和响应式交互不回归。
6. 中英文文案、键盘提交、参数弹层、素材上传、SSE 任务刷新等现有能力保持可用。

## Acceptance Criteria

- [ ] 用户调用账单接口或打开账户页时，结果中不出现 `RESERVE`/`RELEASE`；返回的 `total` 与分页只计算可见类型。
- [ ] 用户账单接口显式传入 `type=RESERVE` 或 `type=RELEASE` 时返回空页；管理员账单接口使用相同筛选条件时仍可返回对应记录。
- [ ] 管理员账单接口仍能查询 `RESERVE`/`RELEASE`，且类型筛选行为不变。
- [ ] 在有历史会话的账户上打开 `/generate`，DOM 不包含活动会话任务内容，显示“开始一段新的创作”空态；不会调用创建空会话接口。
- [ ] 空态点击示例提示词可填入 composer；提交后只创建一个会话和一个首任务，并导航至 `/generate/:sessionId`。
- [ ] 点击“新建会话”后地址回到 `/generate`、活动会话为空、历史列表不新增空会话。
- [ ] `/generate/:sessionId` 仍正确加载并展示指定会话；历史会话点击可切换。
- [ ] 生成页关键内容在桌面和 390px 移动视口居中，`document.documentElement.scrollWidth <= window.innerWidth`。
- [ ] 前端 typecheck、build、单元测试通过；相关 API mapper/service 测试通过。

## Out Of Scope

- 不删除数据库中的 `RESERVE`/`RELEASE` 记录，不改变额度结算、对账或管理员报表数据。
- 不改变生成任务、会话、计费规则或存储 schema。
- 不重做参考截图之外的导航、账户购买和订单交互。
