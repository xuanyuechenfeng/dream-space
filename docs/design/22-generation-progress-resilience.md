# 生成进度展示与长任务同步设计

## 1. 问题与证据

用户看到的空白区域不是规划失败。完整日志显示：

- 22:23:11 规划模型开始请求，22:24:18 返回并完成 preflight。
- 22:24:18.964 图片供应商请求开始，22:24:59 返回 HTTP 200。
- 22:24:52 出现 `Disconnected from the target VM`，随后 Spring 开始 graceful shutdown。
- 22:25:07 连接池已关闭，worker 写入 `task.slot.started` 时失败。

因此，日志中的 executor timeout 是进程关闭阶段的 shutdown warning，不是图片模型在 3-4 分钟后主动超时。进程被停止后，图片供应商虽然已经返回成功，worker 已无法使用数据库连接完成结果结算。

前台另有一个确定的展示缺陷：v2 任务带 `slots` 时，`waiting` 槽位只有状态标题，没有 result/error，也没有 loading 分支，模板因此输出空白；单槽位样式还会隐藏标题并将高度设为 0，空白更加明显。

## 2. 目标

1. 规划完成、图片生成开始前后，结果区域始终有可见的等待/生成状态。
2. 单图、多图槽位保持稳定尺寸，不因状态变化造成布局塌陷。
3. SSE 连接 120 秒生命周期结束、网络断线或事件丢失时，前台仍能通过任务查询获得最新状态和结果。
4. 不把仍在后台执行的任务提前标记为失败，也不改变服务端结算语义。

## 3. 方案

### 3.1 槽位状态渲染

在 `GenerationWorkspaceView` 的槽位渲染中，为 `waiting` 和 `generating` 共用状态占位：图标、可访问状态文本和固定内容区域。`result` 和 `errorMessage` 保持更高优先级。等待文案复用现有 `slotStatusLabel`，中英文行为一致。

样式为槽位占位建立最小高度；单槽位使用方形比例，多槽位使用稳定的卡片高度。这样即使后端尚未写入第一张图片，用户仍能看到任务名称、进度和取消操作。

### 3.2 任务查询对账

在 generation store 中增加轻量级活动任务轮询：会话激活或提交任务后启动单个 5 秒定时器，只刷新 `queued/generating/retrying` 任务；没有活动任务时停止定时器。轮询与 SSE 共存，SSE 负责即时更新，查询负责断线恢复和最终一致性。所有请求继续经过现有 session transition、task refresh version 校验，避免旧会话响应覆盖当前页面。

### 3.3 失败边界

本次不把 worker shutdown warning 转换为用户可见的生成失败。若进程确实在图片返回前停止，任务仍由现有队列重领/结算机制处理；若图片已返回但进程无法落库，运维侧需要保证 worker 进程和数据库在任务执行期间不被提前关闭。

## 4. 验收标准

- `waiting` 槽位不再出现空白，至少显示“等待生成/Waiting”和 loading 图标。
- `generating` 槽位显示“生成中/Generating”和 loading 图标。
- 单槽位、多槽位的输出区域在状态切换前后保持可见且不塌陷。
- 模拟 SSE 断开后，最多 5 秒内通过任务查询更新成功结果。
- 现有 typecheck、build、generation 单测全部通过。
