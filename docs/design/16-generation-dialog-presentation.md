# 图片生成对话框展示改造设计

## 1. 目标

调整图片生成工作台中每条任务的对话展示，使“用户输入”和“图片生成结果”成为两个清晰、可扫描的区域：

- 桌面端：生成结果位于左侧，用户输入位于右侧；
- 生成中：使用低干扰的预览占位、阶段标签和可取消操作，参考提供的“进行中”视觉；
- 生成完成：占位区域平滑切换为真实图片结果，并保留下载、放大预览、再次编辑和重试；
- 移动端：由于横向空间不足，改为结果在上、输入在下的单列结构。

本次只调整前端展示层，不修改生成 API、任务状态枚举、SSE 事件或图片存储契约。

## 2. 信息架构

每个 `.task` 由三层组成：

1. `task-card-header`：状态徽标、生成阶段、参数摘要和额度信息；
2. `task-conversation`：
   - `task-output`（左）：结果舞台；
   - `task-input`（右）：用户原始提示词、参考素材和尺寸/比例摘要；
3. `task-actions`：取消、再次编辑、重试等操作。

生成结果和输入不再共享一条无分组的纵向流。用户输入使用浅蓝灰色气泡，保持右对齐；结果区域使用中性画布，避免和输入气泡竞争视觉层级。

## 3. 状态设计

### 3.1 排队 / 生成中

- 左侧结果舞台显示 16:9 的空白预览画布，带细线几何辅助线、中心环形加载指示和轻微呼吸动画；
- 舞台底部显示 `宽 x 高 · 比例`，右下角显示圆形暂停/取消入口（按钮仍提供可读 `aria-label`）；
- 顶部状态徽标显示“排队中”或当前阶段（例如 `generation started`）；
- 右侧输入气泡展示完整提示词，最多 8 行，超出部分可通过展开/折叠控制查看；
- 不显示空的结果网格，也不在输入气泡内重复放置进度条。

### 3.2 完成 / 部分完成

- 左侧替换为真实结果网格，单图时保持稳定的宽高比，多图时使用紧凑网格；
- 结果图片支持点击放大、悬停下载；
- 顶部状态徽标使用成功图标和额度信息；
- 右侧保留原始输入与参数，便于与结果对照。

### 3.3 失败 / 已取消

- 左侧舞台显示错误或取消状态，保留与生成中相同的画布尺寸，避免任务高度跳变；
- 错误文本位于舞台内，具体后端错误优先于通用文案；
- 操作区提供“再次编辑”和“重新生成”，取消状态显示额度已返还。

## 4. 视觉与交互规范

- 采用现有主题变量（`--surface`、`--border`、`--muted`、`--primary`），不引入新的渐变品牌色；
- 卡片圆角不超过 10px，边框 1px，阴影仅用于浮层；
- 输入气泡右对齐，最大宽度 460px；结果舞台占据剩余宽度，桌面端最小宽度 420px；
- 生成中占位画布使用 CSS 绘制的几何线条，不新增图片资源；
- 所有图标按钮保留 `aria-label` 和 `title`，下载与预览继续使用现有按钮行为；
- 动画遵循 `prefers-reduced-motion`，减少模式下停用呼吸和加载动画。

## 5. 响应式行为

| 视口 | 布局 | 关键规则 |
| --- | --- | --- |
| ≥ 1100px | 结果左 / 输入右，两列 | 结果最小 420px；输入气泡右对齐 |
| 768–1099px | 结果左 / 输入右，窄间距 | 结果列按 52% 分配；参数摘要换行 |
| < 768px | 单列 | 结果在上、输入在下；输入气泡宽度 100%；操作按钮横向滚动 |

## 6. 验收标准

- [ ] 任务列表中输入与结果视觉上分开展示，桌面端输入在右、结果在左；
- [ ] 排队和生成中显示参考图 2 风格的占位舞台，状态文字和尺寸信息可读；
- [ ] 生成完成后真实图片仍可预览和下载；
- [ ] 失败、取消、部分完成状态保持稳定布局并提供对应操作；
- [ ] 768px 与 390px 视口无横向溢出，移动端切换为单列；
- [ ] 现有生成、取消、重试、再次编辑和参数浮层交互不回归；
- [ ] `npm run typecheck`、`npm run build`、相关单元测试通过。

## 7. 实现边界

只修改 `dream_web/src/features/generation/GenerationWorkspaceView.vue` 和 `dream_web/src/styles.css`。任务状态、SSE 刷新、图片下载和预览逻辑复用现有实现；新增的展示辅助函数只负责文案和尺寸计算，不改变持久化数据。
